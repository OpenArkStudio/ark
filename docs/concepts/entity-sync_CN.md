# Entity 增量同步

Kernel 提供拥有型标量捕获及带修订号的发布端／接收端接口。访客房间通过显式公开字段接入 Protobuf 与 Godot C#。通用订阅与嵌套复制仍是提案。

![标量同步流程](../assets/entity-sync-flow_CN.svg)

## 当前能力与边界

| 组件 | 已提供 | 边界 · 契约 |
| --- | --- | --- |
| Kernel | `capture_scalar_snapshot`、`scalar_publisher`、`scalar_replica`；合并变化、原子修订校验与删除标记 | 进程内 C++ 值，由调用者选择授权字段和刷新点；字段／文本上限覆盖重建状态，不代表编码大小 · [标量接口](../reference/kernel_CN.md#标量基线与增量)、[捕获上限](../reference/kernel_CN.md#拥有型标量快照) |
| 房间 v1 | 加入／重连基线、后加入玩家基线、TCP 标量增量与移除；公开字段 100–108，隐藏配置字段 99 | 服务端分配玩家／Entity 身份，客户端请求操作；单个大厅，工作量／输出有界，不提供账号服务或持久化 · [协议、身份与具体上限](../../examples/guest_room/protocol_CN.md) |
| Godot C# | 生成的 Protobuf 消息、共享样本、整体校验后提交房间状态、引擎线程更新场景 | 两端协同升级，使用 JSON 消息体的旧端不兼容；Entity 定义／业务配置仍用 JSON · [兼容契约](../../examples/guest_room/protocol_CN.md)、[客户端](https://github.com/OpenArkStudio/ark-client-godot) |
| Net／arknet | 框架帧交付／传输 IO | 入队不等于应用确认；房间 v1 不提供 ACK／重放、分片或 AOI · [Net 所有权](../reference/network_CN.md) |

原生检查覆盖 C++ 状态流程与房间传输，本机双引擎 Godot 测试覆盖移动、HP／MP、移除与重连。main CI 已在 Linux、macOS、Windows 上通过。这些结果不构成生产容量或通用复制验收。

## 拟议通用契约

以下规则扩展到房间 v1 以外，不代表新增 API、线协议字段或排期。应用仍需定义 Schema 身份、会话授权、刷新接入与具体上限。

| 议题 | 拟议规则 |
| --- | --- |
| 可见状态与身份 | 完整基线仅包含授权状态，省略的授权字段须明确零值／默认值表示。使用运行时 Entity GUID、实例／流代次、Schema／类与稳定成员索引；配置 ID 保持独立。GUID 复用须换代，行须有代次，子引用须包含 Entity 与容器／槽位身份。 |
| 修订号 | 一个流覆盖根 Entity 及其选定嵌套状态，不提供跨根原子事务。在所有者线程冻结基线 R，另行收集后续变化。仅应用基准匹配的增量；忽略重复，使缺口、错误代次／Schema 失效，重连获取新基线。隐藏变化无需推进该接收者的修订号。 |
| 收集与事件 | 业务修改后须显式刷新，不能依赖模块注册顺序；封装具备独立所有权的不可变批次，回调变化进入下一批。不得将借用的 `node*`、`row*`、`entity*` 交给 IO 线程。状态合并须以已知接收者基线为准；`real_time` 可提示提前刷新，但不绕过顺序、授权或上限。事件另定顺序、重复／缺口与保留规则；溢出须报告缺口或终止，不能静默丢弃。状态重置不重放或确认事件。 |
| 会话授权 | 绑定服务端分配的接收者与可见状态，访客身份无需账号服务。`sync_self`／`sync_view` 策略输入与会话授权取交集；绑定／策略缺失时拒绝，仅所有者字段还需 Entity 所有者绑定。客户端 ID 不授予权限或写权。递归过滤子状态，父关系不授予子字段访问权。队伍／公会／地图／AOI 策略另定。 |
| 权限变化 | 交付入队前检查授权。扩权先发基线再发增量；撤权移除客户端状态与未入队越权负载。不可变的已入队负载无法继续授权时关闭流。新流代次替换可见状态，移除省略的字段／行／子 Entity。 |
| 创建与移除 | 初始化／回调完成后发布，初始写入形成基线。删除标记取消未封装状态并防止复活；已入队批次仍排在移除之前。尚未可见的创建后销毁可不出现在状态复制中；事件遵循独立规则。 |
| 恢复与上限 | 接收者进度与全局脏状态分离。限制待发字节数／批次数／年龄、基线大小和重连／重置频率；拒绝超限基线。溢出或入队失败关闭流，断线释放状态，重连安装新基线／流代次。不保留 ACK／重放历史；原地重置与分片留待后续，分片须原子安装并限制组装时间／内存。 |

### 拟议嵌套顺序

| 变更 | 必须得到的结果 |
| --- | --- |
| 新增行 → 更新 | 先以最终值新增，再处理后续更新 |
| 更新行 → 删除 | 删除覆盖该代次的待发更新 |
| 删除行 → 复用行号 | 先删除旧代次，再创建新代次 |
| 清空 → 新增行 | 清空屏障先于新行，覆盖此前行增量 |
| 放入／交换／移除子 Entity | 有序关系或按修订号替换受影响槽位；移除不等于销毁 |
| 销毁子 Entity | 可见销毁前移除关系；抑制未封装更新，已入队批次排在移除之前 |
| 跨容器移动 | 一个有序关系批次或显式可见状态重置；可拒绝不支持的跨根移动 |

嵌套验收须从基线覆盖即时／延迟路径、仅含容器的批次、排队时撤权、GUID 复用、停机与过期引用。现有回调与操作枚举不构成契约验收；旧延迟同步值与拥有型捕获保持分离。

所有者线程规则继续适用：Net 回调通过 Update 交付，HTTP IO 处理器须将 Entity 命令转交所有者线程。跨线程编码须使用拥有型不可变输入、保持完成顺序并限制队列。参见 [Net](../reference/network_CN.md)、[生命周期](application-architecture_CN.md)、[数据模型](data-driven_CN.md)与[数据结构](../guides/data-structures_CN.md)。

[配置导出器](../guides/tools_CN.md)共享索引，不生成通用 C# Entity 运行时。删除／复用索引或改变类型须明确兼容／重置策略；JSON 格式版本不足以标识应用 Schema。正确性验收后再测量负载与所有者线程开销。RPC、持久化、Registry 和热更新不在本范围内。
