# Entity 增量同步提案

**状态：设计提案；本文不定义新的运行时 API 或线协议。** 通用 Entity 同步是 ark 的核心方向：业务模块只修改一次基于 Schema 的状态，由可复用的同步层向客户端交付经过授权的状态变更。本文说明拟议的正确性边界与实施阶段，不将自动复制描述为现有能力。

当前数据模型见[数据驱动](data-driven_CN.md)、[数据结构](../guides/data-structures_CN.md)和 [Kernel 参考](../reference/kernel_CN.md)。[Net](../reference/network_CN.md) 负责框架消息交付，arknet 负责传输 IO。

## 现有基础与缺口

以下源码核对基于 `4e815386259d0576aec6bca53ad056c5863cdf84`，属于源码事实，不代表传输验收结果。

| 范围 | 现有行为 | 本提案的边界 |
| --- | --- | --- |
| Schema | 显式字段与关系索引、标量类型、同步掩码；规范 JSON Schema 与静态配置 | 索引标识 Schema 成员，不代表订阅、修订号或权限 |
| 标量变更 | 类型化的 `node_manager::set_*()` 通过回调提供旧值与新值；相同值直接返回，不触发回调 | 收集受支持的 Entity、行变更路径；直接调用 `node::set_*()` 或修改自定义数据不自动纳入 |
| 表 | 行新增、删除、清空与列更新回调携带表、行、列索引；行号可以复用 | 单独的行号无法区分旧行与替代行；当前列回调采用表掩码 |
| 容器 | 放入、移除、销毁、交换回调；子 Entity 保留 ID 与父关系 | 移除与销毁含义不同；槽位不等于子 Entity 身份 |
| 旧同步机制 | `real_time` 按掩码立即调用同步回调；其他变更收集至 Kernel Update；已有 Protobuf 转换与嵌套容器路径 | 延迟集合保存借用的 `node*`，刷新后清空，不构成持久或带确认的变更日志 |
| 旧交付路径 | `sync_view` 遍历同一地图实例的 `Player`；`sync_self` 进入 `send_to_self()` | `send_to_self()` 当前直接返回成功，没有发送消息；队伍、公会、地图掩码不构成交付策略 |
| 示例 | `guest_room::broadcast()` 读取 Entity 字段，显式构造完整房间 JSON 快照并入队 | 示例快照属于应用代码，不是通用脏字段复制 |

对应实现：[节点管理器](https://github.com/OpenArkStudio/ark/blob/4e815386259d0576aec6bca53ad056c5863cdf84/src/plugins/kernel/node_manager.cpp)、[表变更](https://github.com/OpenArkStudio/ark/blob/4e815386259d0576aec6bca53ad056c5863cdf84/src/plugins/kernel/table_impl.cpp)、[容器变更](https://github.com/OpenArkStudio/ark/blob/4e815386259d0576aec6bca53ad056c5863cdf84/src/plugins/kernel/container_impl.cpp)、[回调收集](https://github.com/OpenArkStudio/ark/blob/4e815386259d0576aec6bca53ad056c5863cdf84/src/plugins/kernel/class_call_back_manager.cpp)、[Kernel 生命周期、转换与交付](https://github.com/OpenArkStudio/ark/blob/4e815386259d0576aec6bca53ad056c5863cdf84/src/plugins/kernel/kernel_module_impl.cpp)、[访客房间](https://github.com/OpenArkStudio/ark/blob/4e815386259d0576aec6bca53ad056c5863cdf84/examples/guest_room/guest_room_module.cpp)。

复用现有路径前需要补齐正确性：仅含容器变更的延迟批次会提前返回；延迟表交换、即时表清空没有完整处理。回调注册也缺少通用的公开注销接口。可复用收集器必须明确所有权、关闭流程与回调重入规则，不能将现有借用指针集合直接作为客户端契约。

## 建议的首版范围

以下阶段 1–2 组成最小同步闭环，采用有序、可靠的 TCP 或 WebSocket 连接。每条活动连接绑定服务端分配的会话、接收者身份与显式字段可见性规则；支持访客会话，无需预先建设账号或认证服务。连接、重连时先发送完整的授权标量基线，再发送具备独立所有权的不可变标量增量，按流维护流代次与修订号。首版还包含 Entity 的创建基线与有序移除标记。

限制待发字节数、批次数、年龄与基线大小。溢出或修订号、Schema 不匹配时断开连接，重连后建立新基线；有需要时再加入显式原地重置。首版不加入重放历史、应用 ACK 协议、基线分片或 AOI；基线超过配置上限时拒绝同步。传输队列必须拥有已接收负载并保持顺序；批次与移除标记无需额外保留 ACK 历史。这些是设计建议，不是已定稿的线协议字段或 API。

## 拟议状态契约

可见状态指某个接收方获准看到的 Entity 字段与关系；流代次（epoch）区分重新建立的同步流，修订号（revision）标识该流内的状态版本。

以下规则是供评审的建议默认值。本文中的名称表示概念，不是已批准的 C++ 方法或消息字段。

### 基线、身份与修订号

接收者先获得**授权可见状态的完整基线**：初期包含选定的标量值，加入嵌套同步后再包含表行与容器关系。基线的「完整」仅限该可见状态，不得因此暴露所有服务端数据。省略的授权字段需要明确零值或默认值表示，使新客户端无需读取服务端私有配置即可重建相同状态。

使用运行时 Entity GUID、实例代次或流流代次、类与 Schema 身份、显式成员索引标识状态。配置 ID 与运行时 ID 保持独立。销毁后复用 GUID 必须产生新代次。复用的表行需要行代次或等价的有序替换身份。子引用同时包含子 Entity 身份与容器、槽位索引。

每个接收者的同步流使用单调递增修订号；增量携带流代次与所需基准修订号。一个同步流覆盖根 Entity，后续嵌套阶段再纳入选定的嵌套状态。修订号无需暴露对该接收者不可见的变更。在所有者线程冻结修订号 R 的基线，另行收集后续变更。客户端安装 R 后，仅应用基准与本地修订号一致的增量。忽略重复批次；发现缺口、错误流代次或不兼容 Schema 时使流失效，不做部分应用。初期关闭连接并在重连后建立新基线，不重放缺失批次。首阶段不覆盖跨根 Entity 的原子事务。

### 收集与合并

在 Entity 所有者线程收集成功的变更。每个 tick 的业务变更完成后，在明确的刷新阶段分离不可变批次，以稳定身份与索引为键。批次构建完成前持有值副本或仅供所有者线程使用的安全句柄；不得将借用的 `node*`、`row*`、`entity*` 交给 IO 工作线程。封装批次期间由回调引发的变更进入下一批次。必须提供显式刷新阶段，不能将模块注册顺序当作可靠的 tick 结束契约。

标量**状态**的多次写入可合并为最终值：HP `100 → 90 → 80` 可只发送 HP `80`。仅在收集器已知该接收者基准状态时，才能省略回到基准值的变更。`real_time` 可以提示提前刷新，但不能绕过修订顺序、授权或队列上限。

状态合并不能替代**事件**。即使 HP 合并，动画、伤害归属或战斗日志仍可能需要两次伤害事件。初始状态复制不包含事件流。后续加入事件交付时，另行定义顺序、重复、缺口和有界保留行为，并按用途决定是否需要确认或重放。状态重置不重放或确认事件。事件无法在约定上限内交付时，应按应用契约报告缺口或终止流，不能以脏字段优化为由静默丢弃。

### Entity 与嵌套数据顺序

初始化与创建回调完成后才发布创建；初始化写入组成基线，不产生针对不存在对象的增量。晚加入的接收者获取新基线。销毁产生带身份的删除标记，取消该代次尚未封装的状态，阻止后续增量使其复活。在首版有序连接中，删除标记排在此前的不可变批次之后，进入具备负载所有权的传输队列；入队后无需额外保留 ACK 历史。队列无法接收时关闭流，重连后用新基线替换状态。接收者尚未见过的 Entity 若在同一区间内创建又销毁，可以不出现在状态复制中；应用事件仍遵循独立规则。

| 变更序列 | 必须得到的结果 |
| --- | --- |
| 新增行后更新列 | 先以最终行值新增，再处理后续行更新 |
| 更新行后删除行 | 删除覆盖该行代次的待发更新 |
| 删除行后复用行号 | 先删除旧代次，再创建新代次 |
| 清空表后新增行 | 清空屏障先于新行；此前行增量失效 |
| 放入、交换、移除子 Entity | 保留关系操作顺序，或按修订号整体替换受影响槽位；移除不等于销毁 |
| 销毁子 Entity | 销毁可见前移除关系；抑制尚未封装的子状态更新，已入队批次保持在移除之前 |

嵌套状态需要递归过滤权限。父关系不授予全部子字段的读取权限。跨容器移动需要一个有序关系批次，或显式重置受影响可见状态；首版可以拒绝不支持的跨根移动。即时、延迟路径都需要验证这些规则，现有操作枚举本身不能证明规则成立。

## 接收者、恢复与线程

应用显式将每个活动会话绑定到服务端分配的接收者身份与允许的可见状态。访客房间会话身份即可使用，不以账号或认证服务为前提。将 `sync_self` 作为所有权策略输入、`sync_view` 作为可见性策略输入，再与会话授权策略取交集。会话绑定或策略缺失时拒绝订阅；仅所有者可见的字段还需明确的 Entity 所有者绑定。客户端提交的 ID 不构成该绑定。队伍、公会、地图成员关系及空间 AOI 由应用后续定义，首版使用显式接收者。服务端向客户端复制不授予客户端写入权限。

显式接收者集合或接收者权限扩大时，先发送授权基线，再发送增量。移出集合或撤权时，丢弃尚未入队的越权负载，并删除相应客户端状态。传输队列中的负载已无法授权时，首版关闭流，不假设不可变的已入队批次还能修改。交付入队前检查授权。新流代次替换旧可见状态状态，并删除新基线中不存在的字段、行与子 Entity。

接收者进度与全局脏集合分离。Net 入队成功不等于应用确认。首版可靠连接只维护活动流进度与有界待发负载，不保留重放或 ACK 历史。配置待发字节数、批次数、基线大小、批次年龄及重连、重置频率上限。溢出时使流代次失效并断开连接；断线释放接收者状态。基线丢失、Schema 不匹配或修订缺口后的重连建立新基线与流代次。基线无法容纳时拒绝同步。原地重置、ACK 与重放历史、基线分片留作后续选择；若加入分片，必须原子安装，并限制组装时间与内存。

Kernel 状态、收集、接收者决策和修订推进均保留在主循环所有者线程。Net 端点回调通过 Update 交付，arknet 管理 IO 工作线程。可选 HTTP 服务端的路由处理器运行在 IO 线程，访问 Entity 状态前必须将命令转交所有者线程。后续只有在数据具备独立所有权且不可变时才能将编码移到其他线程，并保持完成顺序与有界队列。无需新增业务线程池或传输实现。参见 [Net 所有权](../reference/network_CN.md)与[应用生命周期](application-architecture_CN.md)。

## C++ 与 Godot C# 兼容

[原生配置导出器](../guides/tools_CN.md)生成规范 JSON，并可生成 C++、C# 字段索引常量。常量用于共享名称与索引，不生成 C# Entity 运行时、解码器、传输绑定或 Godot 场景集成。显式索引保持稳定，安装基线前校验 Schema 身份。删除、复用索引或改变类型需要声明兼容与重置策略；JSON Schema 格式版本不足以标识应用 Schema 的修订。

选择编码前明确跨语言标量行为：有符号、无符号 64 位整数与 GUID 的精确表示，零值与缺省值，有限浮点数、UTF-8 字符串及枚举处理。不能假设 JSON 数字对所有整数消费者都无损。不支持的值显式报错。C++ 与 Godot C# 共享基线、增量标准样本，覆盖边界与非法输入；解码后的 Godot 场景更新在其主线程执行。二进制布局、消息 ID 与 Schema 校验仍待协议评审，不隐含扩展 `guest_room` JSON 或现有 Protobuf 消息。应用 ACK 协议不在首版范围内。

## 分阶段交付与验收

每阶段可独立评审。下表是后续实现的验收条件，不是本文档变更的测试结果。

| 阶段 | 范围 | 可验证的完成条件 |
| --- | --- | --- |
| 1. 基线 | 有序可靠 TCP/WebSocket、服务端分配的活动会话绑定、显式标量可见状态、Schema 校验及连接、重连基线；保留现有访客房间协议 | 访客会话无需账号服务即可运行；新加入、晚加入、重连的 C++ 客户端重建相同可见状态；隐藏字段不进入负载；拒绝非法 Schema 与超限基线；编码期间不修改状态 |
| 2. 标量增量 | 具备独立所有权的收集器、刷新阶段、按流维护流代次与修订号、合并、创建基线、移除标记及有界断线重连恢复 | HP 连续变更只输出最终状态；相同值写入无输出；重复、缺口、交付中断线后经新基线收敛；回调内变更与刷新前销毁安全；慢客户端溢出时在上限内断开；无需 ACK、重放历史或分片 |
| 3. 嵌套状态 | 行代次、清空、删除、复用、容器放入、移动与销毁；修复或替换不完整旧路径 | 从基线应用上表每种顺序并比较最终状态；覆盖仅含容器的批次、排队时撤权、GUID 复用、关闭与过期引用；无复活和越权子数据 |
| 4. 客户端集成 | Godot C# 适配与相同兼容样本；事件流、ACK、重放或基线分片均需后续独立契约 | C++、C# 状态一致，对非法输入拒绝一致；基线、重置原子应用；场景更新保留在主线程；后续事件的重复、缺口与溢出行为可观测 |

首版实施前需确定流代次与修订号的具体表示、Schema 身份与校验规则、刷新阶段接入方式、会话策略所有权和队列具体上限。线协议映射与客户端 API 另行评审，复用现有 Net、arknet。行替换属于嵌套阶段；ACK、重放、事件交付和分片是后续决策，不构成首版前置条件。正确性验证后再测量负载缩减与所有者线程开销；本地重放不能证明生产容量。RPC、持久化、Registry、热更新和 AOI 不在首版范围内。
