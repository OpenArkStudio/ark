# ARK 访客房间协议 v1

[English](protocol.md)

TCP 帧使用固定的 12 字节头部：第 `0..3` 字节为 ASCII `ARK1`，第 `4..5` 字节为大端无符号 16 位消息 ID，第 `6..7` 字节为必须为零的 16 位 flags，第 `8..11` 字节为大端无符号 32 位正文长度。正文长度不包含头部，最多为 4096 字节。正文为 UTF-8 JSON 对象，不压缩。标记错误、flags 非零或正文超限时，在消息分配和业务回调之前关闭连接。解析器保留不完整头部和正文，分别处理粘连的完整帧；每个连接使用全新的解析状态。

| ID | 方向 | 正文 |
| --- | --- | --- |
| 60000 | 客户端 → 服务端：加入 | `{"name":"Alice","room":"lobby"}` |
| 60001 | 服务端 → 加入者：接纳 | `{"player_id":"1","name":"Alice","room":"lobby","width":960,"height":540}` |
| 60002 | 客户端 → 服务端：移动 | `{"seq":1,"x":120.0,"y":100.0}` |
| 60003 | 服务端 → 已加入者：完整快照 | `{"room":"lobby","players":[{"id":"1","name":"Alice","x":120.0,"y":100.0,"seq":1}]}` |
| 60004 | 服务端 → 客户端：错误 | `{"code":"invalid_message","message":"bounded reason"}` |
| 60005 | 客户端 → 服务端：ping | `{"nonce":1}` |
| 60006 | 服务端 → 客户端：pong | `{"nonce":1}` |

仅提供一个 `lobby`，最多容纳 16 名已加入玩家，不进行账号认证。玩家 ID 是服务端分配的不透明字符串，在本次示例进程内唯一。名称占用 `1..64` 个 UTF-8 编码字节，不含 Unicode C0／C1 控制字符。`seq` 和 `nonce` 必须是 `0..4294967295` 范围内的 JSON 整数，拒绝 `1.0` 等浮点表示。首次移动序列号从 1 开始，后续严格递增。坐标必须为有限值，且分别位于 `0..960`／`0..540` 内；初始位置由服务端确定。

加入成功时，先将接纳消息加入队列，再向所有已加入者广播完整快照。每次接受移动后广播新的权威名单。断线时销毁对应 Kernel 实体，并广播缩减后的名单。重连后重新加入，获得新 ID 和从 0 开始的实体序列号，不恢复旧身份或旧状态。ping 无需先加入。

错误码包括 `room_full`、`already_joined`、`not_joined`、`invalid_message` 和 `stale_sequence`。非法请求不修改实体状态。不支持或方向错误的消息 ID 返回 `invalid_message`；示例头部将这些 ID 映射到内部回调键 60007，避免进入 Net 保留 ID 1／65535 的默认 SS 控制路径。此映射仅用于本地分发，不增加线格式消息。业务错误保留会话，超过工作量或输出限制时关闭连接。协议不保证移动失败重放、持久身份或可靠业务确认。
